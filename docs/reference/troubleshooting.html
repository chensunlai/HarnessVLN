Profile mismatch ​

错误会列出模型要求和环境实际值。典型修复方向：

  • StreamVLN 缺 pose/camera_intrinsics：使用完整 R2R Environment 配置；
  • DualVLN 缺 stand_still 或 pitch -30°：让专用 Bench 引用 DualVLN Env profile；
  • turn 30° 对模型要求 15°：调整真实 simulator profile，不能只改声明；
  • RGB shape/HFOV 不符：同时调整 sensor config 和 profile camera。

不要通过删除 requirements 让启动通过。

最后事件能说明停止前谁在调用什么。outcome 为 denied/invalid/closed/error 时，结合 name、actor、 arguments 与 error 判断权限、schema、写屏障或 handler 问题。

若 timeout 后仍持续出现 VLN 发出的环境动作，检查阻塞 vln.navigate.local/task 是否已返回或被 取消，以及 VLNNavigator.stop() 是否收敛内部 Job。Agent 不应接触内部 Job id 或发送 status/cancel。

若 error_stage == "score"，Task 已经完成，应继续检查 result.json 的 terminal、 environment.json 和 events.jsonl； 此时 metrics 为空只代表 Bench 评分失败。除评分器抛异常外，还应检查它是否返回空映射、空指标名、 bool、字符串、NaN 或 Infinity。stack / execution 阶段则没有可用的 NavigationResult。

stack 错误中若出现 must implement callable methods、required_tools must be a frozenset 或 must declare a NavigationProfile，说明 factory 已返回对象，但对象没有满足对应插件契约；此时 Environment 尚未 start。VLN profile mismatch 会形成 Harness failed terminal，environment 结果为空， 同样不会先启动 simulator。

Agent 返回但任务失败 ​

若 reason 表示 Agent returned without calling stop，Agent 的某条正常分支直接 return。所有业务终点 都应调用 nav.stop；外部取消分支可直接返回，因为 Harness 已进入终止路径。

VLN worker ​

RPC 错误通常附最近 stderr。依次检查：

  1. command/cwd/PYTHONPATH 是否与配置一致；
  2. upstream root 与 checkpoint 是否存在；
  3. worker hello 的 protocol/model/capabilities；
  4. GPU OOM、dtype 和 meta tensor；
  5. Observation channel/shape；
  6. 动作 parser 输出是否在 Environment enum；
  7. request timeout 是否覆盖真实加载时间。

只调大 timeout 会掩盖死锁。先确认 stderr 和 GPU 利用率仍有进展。

多 GPU 模式下先从 result.json.resources 读取 Harness worker PID 与物理卡号，再用 nvidia-smi 确认其 VLN 子进程位于同一物理卡。Runner 使用 spawn 并在导入 GPU 依赖前设置 CUDA_VISIBLE_DEVICES，所以模型/模拟器配置应继续写逻辑设备 0；不要把物理卡号重复写进插件参数。 Habitat 场景加载和原生库日志位于同一 resources 中的 worker_log，路径相对 Run 根目录；这些日志 刻意不转发到终端，以免多个 worker 干扰父进程进度条。

Habitat ​

  • scene not found：核对 data/scene_datasets 软链接和 scene id rewrite；
  • config not found：从 Env YAML 检查 native_factory_params.config_path；
  • sensor missing：检查 config/envs/habitat/*.yaml 的 Hydra defaults 与 habitat.simulator.agents；
  • 距离/坐标异常：不要混用 episode GPS 与 MP3D world；
  • Dual 输入异常：核对原生 sensor orientation 和 Env profile pitch 同时为 -30°。

Isaac / InternUtopia ​

  • 当前两套专用 Bench 若报 scene/USD/policy 缺失，状态与矩阵一致；
  • SimulationApp 是进程级资源，保持 task_parallelism: 1；
  • 高层动作超过 tick 上限说明 locomotion completion signal 未出现，检查 native observation mapping；
  • Kit 首次启动扩展解析较慢，区分首次缓存与持续无响应。

清理残留 ​

cleanup error 出现后先保存 Manifest，再检查 worker、Unity/Kit 和 GPU 进程。根因修复应使插件 stop 幂等且有界；不要在 Runner 外简单吞掉清理异常，否则后续 case 可能绑定到污染资源。

seed 与复现 ​

当前 runner.seed 尚未统一注入各后端。指标不一致时同时核对 simulator、dataset、checkpoint、 worker options、Agent、成功阈值和各插件 seed。Manifest digest 相同只证明 Harness 配置相同， 不证明所有外部随机源相同。
