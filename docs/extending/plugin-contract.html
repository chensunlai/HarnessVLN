插件契约总览 ​

新增模块前先选边界。HarnessVLN 不要求继承抽象基类；只要对象满足 Protocol，并通过 YAML factory 构造，就能接入。结构类型降低依赖，但也意味着 contract test 必须承担运行时保证。

五类扩展点 ​

扩展点输入输出/能力生命周期
NavigationAgentNavContext主动函数调用并最终 stopTask
VLNNavigatorTask + ToolClient + ModuleOutputvln.navigate.* Job 工具Task / Session
EnvironmentEnvironmentEpisode + ModuleOutputnav.* 工具、terminal、resultTask
SpatialMemoryTask + ToolClient + ModuleOutputspatial.* 工具Task 实例，可持久化
BenchmarkdatasetCase stream 与 scoreBench session

只有 Agent 与 Environment 构成最小运行 stack；VLN 和 Memory 都是可选能力。传统规划若与 simulator/navmesh 紧耦合，可直接由 Environment 注册工具，不需要新增核心组件类别。

稳定面与扩展面 ​

稳定面：Protocol 方法、NavTask/NavGoal/Observation/Pose、工具名、现有 schema 语义、terminal 与清理顺序。

扩展面：public、channels、extras、requirements 映射、Environment result、provenance、 插件 params。扩展字段能快速实验，但一旦两个以上插件依赖同一语义，应提升为有文档和测试的协议。

接入前的四个问题 ​

  1. 谁决策？ 组织步骤、选择工具和恢复策略属于 Agent；动作预测内部循环属于 VLN。
  2. 谁拥有原生对象？ simulator/service/robot 连接属于 Environment。
  3. 谁拥有真值？ dataset loader 与 evaluator 属于 Bench。
  4. 状态活多久？ Task 内状态放实例；重 checkpoint 可 session-scope；跨 Task 知识放 Memory 存储。

通用实现要求 ​

目录 ​

  • src/<domain>/*.py 仅放被多个插件复用的基座；
  • 具体插件放在 src/<domain>/<plugin>/，即使初版只有一个文件；
  • 插件 __init__.py 只暴露稳定 factory 入口，内部文件可继续拆分；
  • 新插件需通过 tests/contract/test_plugin_layout.py。

构造 ​

  • factory 使用 module:object，参数可 YAML 化；
  • Environment factory 接受 episode=EnvironmentEpisode，不 import BenchmarkCase，也不读取 truth；
  • 构造函数不应启动昂贵异步资源，启动放入 start；
  • 参数错误尽早抛出具体异常。

能力声明 ​

  • Agent/VLN/Memory 的 required_tools 只列实际调用项；
  • Environment 的 profile 精确写 channel、动作、frame、units 和 camera；
  • VLN requirements 只写模型硬要求，不写偏好；
  • 新 Tool 必须 additionalProperties: false，给写操作标记 writes=True。

Bench 评分 ​

  • score(case, result) 只读取 Bench 私有 truth 和公开的 NavigationResult；
  • 返回非空 Mapping[str, Real]，名称非空，值必须有限且不能是 bool；
  • 缺少必需的环境结果时抛出带字段语义的异常，不返回 NaN/Infinity；
  • Executor 将合法值归一化为 float，将异常或非法返回值隔离为该 Case 的 score 错误。

生命周期 ​

  • 实例默认 single-use；
  • start() 返回具体的 Sequence[Tool]，批次中只能包含 Tool，不能使用 generator 或重复名字；
  • stop 幂等，处理未完全 start、异常、超时和取消；
  • Harness 在调用 start 前登记组件，因此部分 start 失败后仍会调用对应 stop；
  • 后台 task 保留引用并在 stop 中 await；
  • 外部进程按进程组回收；
  • stop 返回后不能再调用原生写操作。

NavigationStack 在生命周期开始前检查各角色的必需方法、required_tools、Environment profile 以及 VLN 工具所有权；VLN/Env requirement 组合也在 Environment.start 前校验。契约错误因此不会 先启动原生环境，未进入 start 的组件也不会收到 stop/result 调用。

可观测性 ​

  • 业务状态通过 Job status、terminal、result 或 tool result 返回；
  • Agent 从 NavContext.output 写摘要，Environment/VLN/Memory 从 start(..., output) 写自己的数据；
  • 模块只用 record/event/frame/unavailable，不拼 Run 路径，也不读取其他模块文件；
  • Environment 选择并提交逻辑 main_camera；无法提供时显式标记 unavailable；
  • 版本身份写入 provenance；
  • 错误包含 case/job/tool 上下文，但不吞原异常类别；
  • 大型逐步数据留在 runs，Git 中提交紧凑、可校验 trace。

最小测试金字塔 ​

层级必测内容
unit成功路径、非法参数、重复 stop、部分 start 失败、取消竞态
contractfactory 可加载、profile/requirements、dataset 公私边界、固定资源版本
integrationYAML -> stack -> 完整 Task -> score -> Manifest；非法指标不污染兄弟 Case
real smoke真实 reset、观测、至少一个动作、goal finish、stop、无残留资源
parity同版本官方 split/evaluator 指标对照

兼容性的判定 ​

只有接口匹配不等于算法兼容。例如 R2R VLN 能调用 ObjectNav Environment 的 RGB-D 与离散动作， 但它没有类别目标训练和 prompt 语义，不能据此标记模型兼容。矩阵应分别记录：

  • mechanical compatibility：工具/profile 可组合；
  • task compatibility：输入目标范式与模型能力匹配；
  • validated compatibility：真实 evidence 与 evaluator 对照。

何时修改核心 ​

优先只新增插件。只有需求跨多个实现且无法用现有 tool/schema 表达时，才修改 ToolBus、runtime 或 公共 schema。核心改动必须补竞态测试与向后兼容说明，因为它的 blast radius 覆盖所有组合。
