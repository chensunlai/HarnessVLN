添加 Environment 与 Bench ​

新模拟器或真实服务通常需要一对插件：Environment 适配执行，Bench 适配任务和评分。二者可以 共享某个上游 dataset 类型，但不能合并成一个对象。

先分别建立插件目录，即使初版各自只有一个文件：

text
src/envs/my_simulator/{__init__.py, environment.py}
src/benches/my_bench/{__init__.py, benchmark.py}
1
2

两个 __init__.py 分别导出 Environment factory 与 Benchmark 类；公共协议或通用 helper 才能留在 src/envs/、src/benches/ 二级目录。

1. 先定义 Case 映射 ​

python
def cases(self):
    for raw in load_split(self.root, self.split):
        goal = NavGoal(
            goal_id=stable_goal_id(raw),
            instruction=public_instruction(raw),
            modality="language",
            public=public_goal_fields(raw),
        )
        task = NavTask(stable_task_id(raw), goal, scene_id=public_scene(raw))
        yield BenchmarkCase(
            case_id=stable_case_id(raw),
            task=task,
            env_setup=native_reset_fields(raw),
            truth=evaluator_fields(raw),
        )

2. 构造 Environment ​

Environment factory 接收不含评分真值的 episode：

python
def from_episode(episode: EnvironmentEpisode, **params) -> MyEnvironment:
    return MyEnvironment(episode, **params)
1
2

EnvironmentEpisode 只有 task 与 setup。构造阶段保存参数，start(task, output) 才建立原生 session、reset 并注册工具。如果 reset 失败，start 应清理已创建的部分资源后再抛出。

3. 声明 profile ​

以物理含义而不是原生名字声明：

python
self.profile = NavigationProfile(
    observation_channels=frozenset({"rgb", "depth", "pose"}),
    motion=MotionProfile(
        tool="nav.move.discrete",
        actions=frozenset({"forward", "turn_left", "turn_right"}),
        frame="my_world",
        units="meters_degrees",
        forward_m=0.25,
        turn_deg=15.0,
    ),
    camera={"height": 480, "width": 640, "hfov_deg": 79},
)

若原生系统使用速度或 waypoint，不必假装是离散 0.25 m。新增对应标准工具和 profile 字段，并先 确认 Agent/VLN 真实需要。

4. 注册导航工具 ​

基础环境一般返回：

  • nav.observe：无参数，只读；
  • nav.move.discrete：enum 来自 profile，writes=True；
  • nav.goal.finish：提交原生 stop/subtask stop，writes=True。

所有动作 handler 使用 lock 串行原生控制，并捕获 start 时的 generation。在 stop 增加 generation； 旧调用拿锁后发现过期就抛 ToolClosedError。

5. terminal 与 result ​

wait_terminal 等待原生环境主动结束。Agent 主动结束时该 future 可以永远 pending，Harness 会取消 wait task。Environment 自身到达动作上限、服务断开或 episode terminal 时应 publish 一次。

result 返回 score 所需但不属于 Agent 输入的执行数据，例如：trajectory、path length、最终距离、 native metrics、动作接受状态。它在 stop 之后仍可读取。

Environment 还负责把选定的原生主摄像头 RGB 帧提交为 output.frame("main_camera", frame, metadata)。 没有合适相机时调用 output.unavailable(...)；不要让 Runner 读取或猜测 simulator sensor。

6. 复合任务 ​

若一个 Case 含多个连续 Goal：

  1. Task 只暴露第一个 Goal；
  2. env_setup 保存完整原生 goal stream，Environment 以 episode.setup 读取；
  3. Environment 维护 goal index；
  4. nav.goal.finish 提交当前原生 subtask；
  5. 返回 done: false 和下一个公开 Goal；
  6. 最后一个 Goal 返回 done: true；
  7. 整个过程只 start/reset 一次。

7. 评分与验证 ​

Benchmark.score 从 Case truth 和 Environment result 计算。先通过 loader/score unit test，再用真实 环境做 reset-render-action-stop smoke。新增模拟器必须至少绑定一个具体 Bench；只有 generic session mock 而没有 case/score 的入口标记为 contract，不写“已兼容”。

Bench YAML 的 benchmark.environment 引用 Env YAML。模型专用传感器差异用 Env 的 extends 表达，再由专用 Bench 配置引用；不要把模型名字写进共享 adapter 条件分支。 Habitat 一类已有原生配置系统的后端，应让 Env YAML 通过 config_path 引用原生文件，不要把完整 simulator 配置展开在 Harness component 参数中。
