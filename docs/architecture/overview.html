总体分层 ​

HarnessVLN 的架构目标不是制造一个包含所有导航范式的基类，而是让变化发生在正确边界内： Agent 组织能力，可选 VLN 保留完整模型，Environment 适配执行系统，Bench 适配任务与评分。

六层职责 ​

Bench / Runner

Bench 流式产生 case 并评分；Runner 只调度完整 Task、收集有序结果。

Harness

为一个 Task 装配组件、建立能力总线、仲裁终止并执行有界清理。

Agent Core

唯一决策主体；固定 workflow 与自由 function-calling loop 都实现同一个 run 契约。

VLN / Memory

作为 Agent 可委托的导航能力与空间状态能力，内部实现保持独立。

ToolBus

用名称、JSON Schema、actor 白名单、写属性和审计事件连接组件。

Environment

把标准导航工具翻译为 Habitat、AI2-THOR、Isaac 或服务调用。

schemas/ 横跨这些层，但只保存小而稳定的数据结构：NavTask、NavGoal、Observation、 Pose、EnvironmentTerminal 和 NavigationProfile。模拟器原生类型不会进入 schema。

另一条配置所有权链是 AgentConfig -> Agent Core + VLNConfig? + MemoryConfig?。Runner 不选择 VLN，Bench 不把评分 truth 交给 Env；CLI 只选择运行入口与两个顶层配置。

Agent + Environment 已经是完整可运行 stack。Agent 可以直接调用原子导航工具，也可以调用 Environment 暴露的原生规划能力；只有需要完整 VLN Job 或空间存储时才装配对应可选组件。

插件可以依赖 harness.contracts、harness.runtime.NavContext、harness.tool_bus.Tool 和 schemas；核心层不反向 import 某个具体插件。唯一的具体绑定存在于 YAML factory。

控制面与数据面 ​

控制面由 Runner、Harness、Job 状态和 terminal signal 组成，回答“谁启动、何时停止、怎样 回收”。数据面由 ToolBus 调用、Observation、动作结果和 memory item 组成，回答“导航期间 传了什么”。分开后，Runner 能批量运行而无需窥探逐步观测，VLN worker 能独立进程运行而不改变 Agent API。

为什么不建立万能 BaseVLN ​

StreamVLN、JanusVLN、DualVLN 的输入历史、输出格式、推理线程和 checkpoint 加载差异很大。 Harness 只要求它们：

  1. 声明导航 profile requirements；
  2. 启动后注册 vln.navigate.* 工具；
  3. Job 执行时只调用授权的导航工具；
  4. 停止时使后台任务和进程静默。

这组边界足够连接，又不侵入模型内部。具体模型可以直接在进程内实现，也可继承现有 RPC navigator 把重依赖放进 worker。

插件作用域 ​

组件支持作用域原因
Benchmarktask-only factory lifecycle一个 Bench session 创建一次，由它流式产生 case
Agenttask工作流与对话历史不能跨 case 泄漏
Environmenttask原生 session 和场景状态按 Task 隔离
Memorytask 实例，可持久化文件连接短寿命，知识可跨 Task
VLNtask 或 session大模型可在一个 Bench/交互 session 内跨 Task 复用 worker/checkpoint

session-scoped VLN 在单进程 session 内要求串行 Task，防止同一 worker 被两个环境同时绑定。 配置 GPU 设备池后，每个 spawn worker 持有独立 navigator 并在进程内部串行，因此可跨 GPU 并行。 不同 Bench session 不会因为属于同一次 Run 就共享模型状态。

扩展点不是所有内部函数 ​

首要公开扩展点只有五个：NavigationAgent、VLNNavigator、Environment、SpatialMemory 和 Benchmark。Tool 名与公共 schema 是它们之间的协议。Runner、terminal arbitration、RPC transport、Manifest writer 属于基础设施；只有出现跨插件的真实需求时才扩大接口。

运行产物不是第六类插件。RunOutput -> BenchOutput -> EpisodeOutput -> ModuleOutput 是核心基础设施， 只分配隔离作用域、原子写结构化文件并关闭媒体流；Bench、Agent、VLN、Memory、Environment 各自 提交所属数据。Runner 只汇总状态、指标、文件引用和输出错误，不获取相机帧或插件私有状态。
