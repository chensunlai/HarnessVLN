Agent Core ​

Agent 是 HarnessVLN 的主体。公共契约刻意只有一个入口：

python
class NavigationAgent(Protocol):
    required_tools: frozenset[str]

    async def run(self, context: NavContext) -> None: ...
1
2
3
4

一个 Task 只调用一次 run。固定流程和自由循环的差异完全留在这个方法内部，不需要两套 Runner。 VLN 不是 Agent 的前置条件：NavigationStack(agent, environment) 本身就是完整组合。Agent 可以直接 观察并执行原子动作，也可以使用 Environment 注册的规划工具；vln 和 memory 只按需要装配。

NavContext 提供什么 ​

字段/属性用途
task当前公开 NavTask；复合任务开始时只含第一个 Goal
execution_id本次执行身份，可用于日志关联
tools受 actor 白名单限制的原始 ToolClient
cancelledHarness 开始终止时置位的 asyncio.Event
outputAgent 专属运行输出作用域，不暴露文件路径
navobserve / move_discrete / finish_goal / stop 便捷接口
vlnstart / status / cancel Job 接口
spatialsearch / remember 空间记忆接口

便捷接口不绕过 ToolBus；所有调用仍会权限校验、schema 校验和审计。

当前 Agent 1：透传 VLN ​

PassthroughVLNAgent 代表“模型本身就是完整导航策略”的最短路径：

text
current instruction
  -> vln.navigate.start
  -> poll status until terminal
  -> nav.goal.finish
      | done=false -> use returned next instruction, repeat
      ` done=true  -> nav.stop(completed)

它不获取 Observation，也不要求 VLN 每次只输出一个动作。观察与动作由 VLN Job 自主反向调用。 因此 StreamVLN、JanusVLN、DualVLN 的内部范式都可保持原样。

共享 run_vln_job helper 区分两种取消：Task 仍运行但 helper 被独立取消时，它调用 vln.navigate.cancel；Harness 已开始终止并设置 context.cancelled 时，它直接传播取消，由 VLNNavigator.stop() 收敛全部 Job。这样不会在 ToolBus 封写后再发送 cancel 写调用。

当前 Agent 2：标准 NormalAgent ​

NormalAgent 是仓库中的自由 function-calling 基线。它参考 nanobot 初始提交中的 AgentLoop 只保留“模型调用、工具执行、结果回灌、继续循环”四步，去掉 channel、session、hook、subagent、 memory compaction 和消息总线等与导航基座无关的功能。

text
NavTask + ToolClient.specs
  -> responses.create(tool_choice=required, parallel_tool_calls=true)
  -> one function_call, or 2-4 consecutive nav.move.discrete calls
  -> ToolClient.call(canonical_name, arguments) in output order
  -> native function_call_output(call_id, result)
  -> repeat until nav.stop

实现直接遵循 OpenAI Function calling 协议。模型正文不会被当作动作 JSON 解析；唯一的 JSON 解析对象是原生 function_call.arguments。 每轮返回的 reasoning/output item 会原样加入下一轮输入，工具结果使用相同 call_id 回灌。

为什么仍经过 ToolBus ​

模型只看到 ToolClient.specs 产生的工具描述，不拿 handler 或 Environment 对象。Responses API 使用扁平函数定义，NormalAgent 在边界上完成两项映射：

  • Harness 名字 nav.move.discrete 映射为模型名字 nav__move__discrete，调用时反向查表；
  • provider-neutral ToolSpec 映射为 Responses 的 type/name/description/parameters/strict。

之后仍调用 context.tools.call，所以白名单、JSON Schema、停止写屏障和审计全部生效。工具异常会 以 {"ok": false, "error": ...} 回给模型，让下一轮恢复。模型请求只对连接错误、超时、429 和 可重试 5xx 做有界指数退避；耗尽重试或确定性请求错误才上抛给 Harness。

当前工具 schema 保留 Harness 的可选字段语义，因此 Responses 定义显式使用 strict: false，最终 参数仍由 ToolBus 严格校验。一个模型轮次通常只允许一个调用；唯一例外是最多四个连续 nav.move.discrete，Agent 按输出顺序串行执行。混合 Observation、VLN、Memory、Goal 或 Stop 的批次 会在写入 ToolBus 前整体拒绝，因此不会产生无序副作用；Runner 的完整 Task 并行不受影响。

NormalAgent 能组织什么 ​

config/agents/normal_agent.yaml 是同时启用 VLN 与 Memory 的组合示例，显式列出它可见的能力：

params:
  model: gpt-5-mini
  max_iterations: 80
  max_actions_per_turn: 4
  reasoning_effort: medium
  model_retries: 3
  guidance: "Optional combination-specific instructions"
  tools:
    - nav.observe
    - nav.move.discrete
    - nav.goal.finish
    - vln.navigate.start
    - vln.navigate.status
    - vln.navigate.cancel

nav.stop 由 Harness 自动加入 Agent 客户端。配置中的其他工具必须由所选 Environment、VLN 和 Memory 实际注册，否则 Agent 启动前就会失败。删减 tools 即可得到纯直接导航、只委托 VLN 或 不使用 Memory 的组合，不需要改 AgentLoop；同时把不需要的 vln / memory 引用设为 null。 模型或任务组合特有的策略放在 guidance，它会追加到通用导航提示，而不是耦合进 AgentLoop。

传统导航器若依赖 simulator navmesh、地图服务或真机定位，应由相应 Environment adapter 注册规划 工具，Agent 像调用原子动作一样调用它。基础层不增加必选 Planner 组件；纯 Agent 内部规划也无需 经过新的插件接口。

工具结果以紧凑 JSON 回灌；小型数组保留数值，其他大型数组保留 shape/dtype。nav.observe 的 RGB 会编码成 Responses 原生 input_image，Depth 压缩成中心值和 3×3 网格摘要，并保留 Environment 声明的深度标定元数据。这样 VLN Job 可负责主导航，NormalAgent 也能直接完成视觉检查和短程纠偏， 而 ToolBus 与 Environment 仍传递 provider-neutral Observation。

固定 workflow 仍然兼容 ​

固定工作流和自由循环都是 NavigationAgent 插件。前者把阶段写在 run 内，后者由模型逐轮选择 工具；Harness 对二者只调用一次 run(context)。删除旧的固定句子拆分器不会删除这种扩展能力， 只是基座不再把一个未经验证的拆分策略当作默认 Agent。

Agent 的责任 ​

  • 只声明实际会调用的 required_tools；
  • 解释 VLN Job terminal，而不是把 succeeded 直接等同整 Task 成功；
  • 在复合任务中处理 nav.goal.finish 返回的新 Goal；
  • 收到取消或自身取消时关闭 VLN Job；
  • 正常返回前调用 nav.stop；
  • 把 workflow 状态保留在实例内，不写全局变量。

Agent 不负责加载 dataset、reset 环境、计算指标、结束原生进程或汇总 Manifest；它只向 context.output 提交自己的运行摘要。

选择哪一种 Agent ​

场景建议
评测一个端到端 VLN 原始能力PassthroughVLNAgent
动态选择直接导航、VLN 与 MemoryNormalAgent
验证特定规划/恢复流程新增独立 workflow Agent 插件
复现论文固定阶段流程把阶段明确写进一个 workflow Agent

不要把特定论文 workflow 塞进 Harness runtime；它应与透传 Agent 一样是可替换插件。
