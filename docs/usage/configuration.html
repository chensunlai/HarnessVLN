配置引用 ​

HarnessVLN 不让 CLI 同时拼装 Bench、Env、Agent、VLN 和 Memory。配置按所有权引用：

text
RunnerConfig -> BenchConfig[] -> EnvConfig
AgentConfig  -> Agent Core + VLNConfig? + MemoryConfig?
1
2

这不是把 Bench 与 Env 合并。Bench 仍负责数据与评分，Env 仍是独立执行插件；只是由 Bench 选择与该评测协议匹配的环境入口。VLN 和 Memory 同理仍是独立插件，但由 Agent 配置选择。

两种入口 ​

批量评测只需要 Runner 与 Agent：

bash
PYTHONPATH=src python -m harness.cli run \
  --runner config/runners/r2r_streamvln.yaml \
  --agent config/agents/passthrough_streamvln.yaml
1
2
3

单环境交互只需要 Environment 与 Agent。CLI 输入一条导航指令，扮演临时任务源；Task 内仍由 Agent 主动观察、行动并调用 nav.stop：

bash
PYTHONPATH=src python -m harness.cli env \
  --environment config/envs/dummy.yaml \
  --agent config/agents/passthrough.yaml
1
2
3

顶层没有 --vln 或 --memory，因为它们是 Agent 能力；也没有独立的 --benchmark，因为 Runner 已引用 Bench，而 Bench 已引用 Env。

一个 Runner 可以引用多个 Bench。bench_parallelism 控制 Bench 级并发，task_parallelism 控制每个 Bench 内完整 Task 的并发；两者都不会驱动 observe-act。

devices 是允许使用的物理 GPU 列表。存在该字段时，Runner 用 spawn 启动 GPU 隔离进程并自动 设置每个进程的 CUDA_VISIBLE_DEVICES。因此 VLN 配置中的 device: cuda:0 与 Habitat 配置中的 gpu_device_id: 0 都表示进程内逻辑卡 0。workers_per_device 默认 1；可用 slot 数等于 len(devices) * workers_per_device，task_parallelism 不能超过 slot 数。没有 devices 时保持 原来的单进程 asyncio 执行路径。

root 是实验总目录，每次执行会在其中创建唯一 Run 子目录。run_id 可选，仅适合外部系统已经 分配唯一身份的情况。视频默认开启但不强制：Environment 能提供 main_camera 时保存 H.264 MP4， 否则记录 unavailable。required: true 才把相机缺失或编码错误计为任务失败。

runner:
  max_cases: 1
output:
  root: runs/r2r_streamvln_smoke

加载器检测引用循环，并用 JSON Schema 校验每类配置。解析后的数据、全部源文件绝对路径和 SHA-256 digest 会进入 Manifest。若覆盖同一组件的 factory，该组件子树会先重置，避免旧 params 泄漏给新实现。

ComponentSpec ​

字段含义默认值
factorymodule:object 可调用入口必填
params传给入口的关键字参数{}
scopetask，或 VLN 可用的 sessiontask
serial声明共享资源要求串行false

为什么不是 scope: run

一次顶层 Run 可以同时包含多个 Bench，但每个 Bench 都创建自己的 stack factory 和 VLN 实例；交互 入口也有独立会话而没有 Runner。因此复用边界统一命名为 session：批量模式是一段 Bench session， 交互模式是一段 CLI session。配置加载器不再接受含义不准确的 scope: run。

Environment factory 额外收到 episode=EnvironmentEpisode，其中只有公开 task 和 reset 所需 setup，没有 Bench 评分 truth。Agent、VLN 与 Memory factory 只收到自己的 params。

作用域与并行约束 ​

Agent、Environment 和 Memory 当前只支持 task scope。VLN 可使用 session scope，在一个 Bench 执行或一个交互会话内复用 checkpoint/worker。单进程模式要求该 session 内 Task 串行；GPU 设备池 为每个 worker 创建独立 session VLN，因此不同 GPU 可以并行。不同 Bench 不共享 VLN 实例。任一组件声明 serial: true，或 Memory 开启 writeback，不仅要求 task_parallelism: 1；当 Runner 引用多个 Bench 时也要求 bench_parallelism: 1。App 会在启动任何 Bench 前报告冲突来源。

runner.seed 会进入配置摘要和 Manifest，但尚未统一注入 Python、NumPy、Torch、模拟器与模型 worker；需要可复现时仍应在各插件中显式固定 seed，并记录上游版本。
