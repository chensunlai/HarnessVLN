运行结果与产物 ​

run 模式为每次执行创建独立 Run 目录。顶层文件只做全局索引，Bench、Episode、Environment、 Agent、VLN、Memory 各自保存所属数据，避免 Runner 读取模拟器观测或插件内部状态。 env 交互模式当前只显示单 Task 结果，不创建批量产物。

默认 Run ID 由 UTC 时间、解析配置 digest 前缀和随机后缀组成，因此同一 output.root 下的运行 不会互相覆盖。显式设置 output.run_id 时，目标目录必须尚不存在。

数据所有权 ​

文件写入方内容
manifest.jsonRunOutputRun 状态、配置引用、全局指标、Bench 索引
summary.jsonBenchOutputBench 状态、错误计数、指标、Episode 索引
episode.jsonBenchmark公开 Task、reset setup、稳定 case 身份；不含评分 truth
result.jsonBenchmarkExecutorterminal、逐 case 指标、错误阶段、其他文件引用
environment.jsonEnvironmentprofile、trajectory/native metrics 等最终结果、媒体索引
components/*.json对应 Agent/VLN/Memory该模块主动提交的配置与运行摘要
events.jsonlToolBus/Harness按 sequence 排列的工具调用审计
artifacts/<module>/对应模块视频等大文件及其逐帧元数据

Runner 不调用 env.rgb、不猜 sensor key，也不读取模型对象。Harness 只给模块一个隔离的 ModuleOutput；模块调用 record()、frame() 或 unavailable()，Episode 结束时统一关闭流并收集 输出错误。可选组件未配置或模块没有提交内容时，不创建空占位文件。新模块不需要修改 Runner。

manifest.json 保持紧凑，消费者沿相对 path 进入 Bench。config/resolved.yaml 保存完整解析后的 Runner/Bench/Env 与 Agent/VLN/Memory 配置图；sources.json 保存源文件绝对路径和同一 digest。

Bench 与 Episode ​

summary.json 的 episodes[] 按 Bench 输入 index 排序，每项包含 case_id、status、metrics、 错误摘要以及指向 result.json 的相对路径。case_counts 分开统计：

  • task_failures：failed、timeout、cancelled 等非成功 terminal；
  • case_errors：stack、execution 或 score 阶段异常；
  • cleanup_errors：组件和 Bench session 清理错误；
  • output_errors：可选媒体编码或关闭错误。

result.json 是单 Episode 的最终索引。它保留 execution_id、task_id、terminal、metrics、 environment_path、events_path、cleanup/output errors。使用 GPU 进程池时还包含实际调度结果：

json
{
  "resources": {
    "worker_id": 1,
    "pid": 12345,
    "gpu": {"physical_device": 3, "local_device": 0},
    "worker_log": "benches/000-r2r_ce-val_unseen/logs/worker-001-gpu-3.log"
  }
}

同一资源记录也进入 summary.json 对应的 episodes[]，便于不打开每个 Episode 就检查分配。 worker_log 相对 Run 根目录，保存该进程内 Habitat、模型及原生库的 stdout/stderr；同一 worker 处理的多个 Episode 会引用同一个追加日志。环境大结果和完整审计不复制进 result.json。

error_stage 表示证据完整度：

stage已完成到哪里可用证据
stackstack 尚未构造完成episode.json、错误文本
executionstack 已构造，执行抛异常已经提交的模块文件、错误文本
scoreTask 完成，评分失败terminal、Environment、events 全部保留

主摄像头视频 ​

Environment 是唯一知道 sensor 语义的组件，因此它选择哪个原生 channel 是主摄像头，并以逻辑名 main_camera 提交 RGB 帧。Habitat 使用配置的 rgb，RoboTHOR 使用 event RGB，Isaac 使用 observation_channels.rgb 映射后的原生字段。

yaml
output:
  root: runs/r2r_streamvln
  video:
    enabled: true
    required: false
    fps: 10
    codec: libx264

默认值就是上例。环境没有主摄像头时，environment.json 记录 streams.main_camera.status: unavailable 和原因，不创建空视频；禁用视频时记录 disabled。 成功流记录 MP4 相对路径、编码、帧数、宽高、字节数和 SHA-256。旁边的 main_camera.frames.jsonl 保存 frame_index、source time、动作/原生 tick index 等帧元数据。 设置 required: true 会把相机缺失或写帧失败提升为任务失败；流关闭阶段的编码错误至少会形成 output_errors，使 Bench、Run 和 CLI 失败，且不篡改已经形成的导航 terminal。

写入保证 ​

JSON/YAML 使用同目录临时文件、flush、fsync 和 os.replace 原子更新。视频先写隐藏 partial MP4， 编码器正常关闭且文件非空后才原子改名；失败时保留结构化错误而不留下正式空视频。

各层 schema 独立版本化：顶层 Manifest 当前为 v3，Bench、Episode 和模块记录当前为 v1。消费者 应先检查版本、使用相对路径，并容忍新增字段，不依赖 JSON key 顺序。
